# 평면 픽셀 배틀 체스 재설계

## 목표

현재의 원근 3D 체스판을 완전한 탑다운 평면판으로 바꾸고, 정지 그림을 CSS로 들썩이던 캐릭터를 여러 프레임으로 실제 동작하는 독자적 픽셀 캐릭터로 교체한다. 말을 잡을 때는 약 4초 동안 준비·연타·강타·피격·죽음이 이어지며, 타격 정지와 효과음으로 1990년대 아케이드 액션게임 같은 속도감과 타격감을 낸다.

특정 상용 게임의 캐릭터·프레임·사운드를 복제하지 않는다. 큰 머리와 무기, 과장된 스쿼시·스트레치, 빠른 준비와 강한 반동이라는 액션 문법만 사용한다.

## 범위

### 포함

- 완전한 정사각형 탑다운 체스판
- 백·흑 6종, 총 12개 캐릭터 외형
- 공통 동작: 대기, 걷기, 피격, 회복, 승리
- 말별 동작: 공격 준비, 연속 공격, 마무리 공격, 죽음 진입
- 말별 약 4초 전투 타임라인과 동기화된 사운드
- 기존 기능 유지: 훈련, 혼자, 둘이서, 왕 규칙 스위치, 메뉴 최소화, 호버 미리보기, 발밑 강조, 승리 폭죽
- 저사양 및 `prefers-reduced-motion` 대응
- `?fx` 연출 시험 화면 확장

### 제외

- 특정 게임 캐릭터 또는 사운드의 복제
- 전투 시 별도의 횡스크롤 장면으로 전환
- 3D 모델 및 원근 카메라 유지
- 온라인 대전, 계정, 서버 기능

## 시각 방향

샘플로 승인된 백색 나이트를 기준으로 한다.

- 굵고 또렷한 픽셀 외곽선
- 큰 투구·머리·무기와 작은 몸통의 치비 비율
- 백군: 은백색 갑옷, 금색 장식, 파란 천
- 흑군: 짙은 흑철 갑옷, 적동색 장식, 붉은 천
- 각 말은 멀리서도 구별되는 투구와 무기 실루엣을 가진다.
- 배경과 그림자는 스프라이트에 굽지 않고 게임에서 별도로 그린다.
- 모든 프레임은 투명 배경 PNG이며, 동일한 셀 크기와 공통 발 기준선을 사용한다.

### 말별 실루엣

- 킹: 왕관형 투구와 큰 투척검
- 퀸: 높은 관모와 산성 마법봉
- 룩: 성벽형 중갑과 팔 대포
- 비숍: 뾰족한 주교관과 전기 지팡이
- 나이트: 말머리 투구와 랜스 해머
- 폰: 작은 둥근 투구와 짧은 창

## 스프라이트 자산 구조

말 종류별로 백색 원본 시트를 제작한다. 흑색은 단순 CSS 필터가 아니라 별도 색상 시트로 내보내 색이 탁해지지 않게 한다. 단, 백·흑은 동일한 프레임 배치와 기준점을 공유한다.

각 프레임 셀은 동일한 크기이고 캐릭터의 발 중심을 앵커로 사용한다. 프레임마다 캐릭터가 잘리거나 중심이 흔들리지 않도록 투명 여백을 포함한다.

### 공통 애니메이션

| 상태 | 권장 프레임 | 반복 |
|---|---:|---|
| idle | 4 | 반복 |
| walk | 6 | 반복 |
| hit | 3 | 1회 |
| recover | 3 | 1회 |
| cheer | 4 | 반복 또는 2회 |

### 말별 애니메이션

| 상태 | 권장 프레임 |
|---|---:|
| anticipation | 2~3 |
| attack-a | 4~6 |
| attack-b | 4~6 |
| finisher | 5~8 |
| death-entry | 3~5 |

프레임 수는 움직임에 필요한 만큼만 사용한다. 같은 그림을 위치만 바꾼 프레임은 허용하지 않는다. 달리기는 양다리가 실제로 교차하고, 공격은 팔·몸통·무기 실루엣이 달라지며, 피격은 머리와 몸이 반대 방향으로 지연되어 움직여야 한다.

## 렌더링 구조

### 평면 좌표계

- `--tilt`, 원근 `perspective`, 판의 `rotateX`, 캐릭터의 `--cam` 역보정을 제거한다.
- `#board`는 화면에 평행한 정사각형이며 모든 칸은 같은 화면 크기다.
- `--flip`은 3D 회전이 아니라 판 전체의 180도 회전에 사용한다.
- 판을 돌려도 캐릭터와 글씨는 다시 180도 역회전해 항상 똑바로 보이게 한다.
- 이펙트 좌표는 모두 평면 픽셀 좌표를 사용한다.

### 캐릭터 플레이어

각 말 요소는 다음 상태를 가진다.

- `pieceType`: K/Q/R/B/N/P
- `side`: white/black
- `state`: idle/walk/attack/hit/death/cheer
- `frame`: 현재 프레임 번호
- `facing`: left/right
- `anchor`: 칸 안의 발 위치

프레임 재생은 `requestAnimationFrame` 하나가 모든 캐릭터를 갱신한다. 캐릭터마다 별도 타이머를 만들지 않는다. 상태 정의표는 프레임 시작점, 프레임 수, 초당 프레임 수, 반복 여부를 가진다.

CSS `background-position`으로 시트의 프레임을 선택한다. 이동 자체는 기존처럼 말 요소의 `transform`을 사용하되, 걷기 프레임과 위치 보간을 동시에 재생한다.

### 기존 3D 대체 모델

현재 `sprites.png` 로딩 실패 시 보이는 CSS 3D 모델은 제거하지 않고 비상 대체로 남긴다. 다만 기본 경로와 Vercel 빌드는 새 픽셀 시트를 사용한다. 새 시트를 못 불러오면 게임 규칙과 클릭은 계속 동작해야 한다.

## 전투 연출

전투는 공격자와 방어자가 목적지 칸 주변에서 약 1.25~1.35배 확대되어 진행된다. 판 전체를 가리지 않고, 주변 칸의 클릭은 `locked` 상태로 잠긴다.

공통 리듬:

1. 접근 및 준비: 0.5~0.8초
2. 1차·2차 연타: 1.0~1.5초
3. 마무리 강타: 0.5~0.8초
4. 공격자 회복 및 방어자 죽음: 1.0~1.4초

각 타격에는 다음을 조합한다.

- 60~90ms 타격 정지
- 공격자 무기 잔상
- 방어자 3프레임 피격과 위치 반동
- 작은 충격선 및 먼지
- 마무리에서만 큰 화면 흔들림과 큰 충격파
- 서로 다른 음높이의 타격음으로 연타 횟수를 귀로 구분

### 말별 타임라인

- 나이트: 웅크림 → 점프 → 작은 내려찍기 2회 → 높은 점프 → 큰 내려찍기 → 짜부러짐
- 룩: 장전 → 작은 포탄 2발 → 반동이 큰 주포 → 대폭발 → 실제 캐릭터 시트 8조각과 금속 파편
- 비숍: 지팡이 회전 → 전기 3연타 → 강한 낙뢰 → 흰 섬광 → 검게 타서 재로 소멸
- 퀸: 작은 산성탄 3발 → 큰 산성 파동 → 온몸이 강한 초록색 → 아래에서부터 무너져 웅덩이로 용해
- 킹: 검광 2회 → 준비 회전 → 큰 칼 투척 → 칼이 박힘 → 뒤로 쓰러짐
- 폰: 짧은 창 찌르기 3회 → 몸을 실은 마지막 찌르기 → 기존 모래 소멸

## 사운드

외부 음원 없이 Web Audio API로 제작한다. 기존 `tone`·`noise`를 확장해 다음 레이어를 조합한다.

- 발걸음·점프: 짧은 저역 충격음
- 근접 연타: 고역 슬래시 + 짧은 중역 충격음
- 강타: 저역 붐 + 노이즈 + 60~90ms 무음에 가까운 타격 정지
- 룩: 장전 금속음, 소형 포성 2회, 주포 저역 폭발
- 비숍: 상승 전기음, 불규칙 빠지직, 낙뢰 저역
- 퀸: 점성 있는 산성 발사음, 지글거림, 용해 노이즈
- 킹: 검 회전음, 투척음, 금속이 박히는 소리
- 폰: 가벼운 찌르기 3회, 마지막 무거운 타격

브라우저 자동재생 정책을 따르며 첫 사용자 입력 전에는 소리를 재생하지 않는다. 음량은 기존 효과음보다 과도하게 커지지 않게 마스터 게인을 둔다.

## 상호작용과 접근성

- 평면판에서도 칸 클릭 영역은 캐릭터 그림과 무관하게 전체 칸 크기를 유지한다.
- 기존 호버 미리보기와 움직일 수 있는 말의 발밑 강조를 보존한다.
- 전투 중 입력은 잠그고, 종료 후 정확히 해제한다.
- `prefers-reduced-motion: reduce`에서는 연타 횟수를 줄이고 흔들림·잔상을 제거하며 전체 전투를 약 1.5초로 단축한다.
- 작은 화면에서도 판 전체가 잘리지 않아야 하며 가로 스크롤을 만들지 않는다.

## 성능 기준

- 단일 애니메이션 루프 사용
- 동시에 살아 있는 파티클 최대 120개
- 파티클은 DOM 풀 또는 짧은 수명으로 재사용하고 전투 종료 시 0개가 남아야 한다.
- `transform`과 `opacity` 중심으로 애니메이션하고 레이아웃 속성 변경을 피한다.
- 권장 목표: 데스크톱 60fps, 일반 휴대폰 30fps 이상
- 새 이미지 전체는 WebP 또는 최적화 PNG 기준 4MB 이하를 목표로 한다.

## 제작 순서

1. 평면판 좌표계와 기존 캐릭터로 기능 보존 검증
2. 나이트 완성 시트와 프레임 플레이어 구현
3. 나이트 4초 전투를 끝까지 연결해 품질 기준 확정
4. 룩·비숍·퀸·킹·폰 순서로 자산과 타임라인 추가
5. 흑색 시트 제작 및 양 진영 검증
6. `?fx`에서 모든 상태·공격·죽음 단독 재생
7. 실제 대국, 훈련, AI, 판 돌리기, 메뉴 최소화 회귀 검증
8. GitHub push 후 Vercel 자동 배포와 공개 주소 검증

## 검증 기준

- 판의 64칸이 화면상 동일 크기이고 모두 클릭 가능하다.
- 판 돌리기 전후 말과 글씨가 똑바로 보인다.
- idle과 walk에서 같은 정지 그림을 단순 이동한 프레임이 없다.
- 6개 말 모두 준비·연타·마무리·죽음이 구분된다.
- 타격 효과음과 피격 프레임의 시작 오차가 1프레임 이내다.
- 전투 종료 후 `locked=false`, 시체·파티클·타이머가 남지 않는다.
- 혼자·둘이서·훈련과 왕 규칙 두 모드가 모두 정상이다.
- 승리 폭죽은 승리 때 한 번만 표시되고 패배·무승부에는 표시되지 않는다.
- 콘솔 오류와 자체 점검 실패가 없다.

## 위험과 대응

- 생성형 이미지의 프레임 일관성 부족: 말 하나씩 제작하고 동일한 팔레트·셀·앵커 검사를 통과한 시트만 채택한다.
- 프레임 잘림: 각 시트를 자동 분석해 투명 경계와 셀 침범을 검사한다.
- 긴 전투로 흐름 저하: 기본은 요청대로 약 4초, reduced-motion에서는 단축한다.
- 파일 크기 증가: 백·흑 팔레트와 공통 프레임 배치를 유지하고 시트를 최적화한다.
- 기존 3D 이펙트 좌표 잔존: `--cam`, `rotateX`, `translateZ` 사용처를 전수 검색해 평면용으로 교체한다.
